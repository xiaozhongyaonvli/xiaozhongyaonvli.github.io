# 线程和进程到底有啥区别？线程在 JVM 里独享了什么？

> 这两个问题经常一起被问到，特别是面试的时候。之前我对"线程私有"这块理解得比较模糊，这次直接翻了 JVM 规范（JVM SE8 Specification, Chapter 2）把它搞透了。

## 先搞清楚进程和线程

### 进程是什么

简单讲，进程就是一个**正在运行的程序**。你双击打开一个 IDEA，操作系统就给它分配了一块独立的内存空间，包括代码段、数据段、堆、栈等等，这整个东西就是一个进程。

关键词：**独立**。每个进程有自己的地址空间，进程 A 是访问不到进程 B 的内存的（除非通过 IPC 进程间通信）。

### 线程是什么

线程是进程里面更小的执行单元。一个进程至少有一个线程（主线程），也可以有多个。

关键词：**共享**。同一个进程里的线程共享进程的代码、数据、堆内存、打开的文件描述符等资源。但每个线程有自己**独立的**执行上下文——程序计数器、寄存器、栈。

> 我觉得最核心的区别就这一句话：**进程是资源分配的基本单位，线程是 CPU 调度的基本单位**。进程有自己的一整套资源，线程只保留运行所必需的最小上下文，其余跟兄弟线程共享。

### 对比放在一起看

| | 进程 | 线程 |
|---|---|---|
| 内存空间 | 独立，互相隔离 | 共享所属进程的内存 |
| 创建开销 | 重量级，需要分配完整资源 | 轻量级，只需栈和寄存器 |
| 通信方式 | IPC（管道、消息队列、共享内存等） | 直接读写共享变量（但要注意同步） |
| 上下文切换 | 慢（要切换整个地址空间） | 快（只切换栈和寄存器） |
| 崩溃影响 | 一个进程挂了不影响其他进程 | 一个线程挂了可能导致整个进程崩溃 |
| 独立性 | 完全独立 | 依赖于所属进程 |

### 用个类比

进程就像一套房子——有自己的厨房、客厅、卫生间，完全独立。线程就像住在同一套房子里的室友——共享客厅和厨房（堆、方法区），但每个人有自己的卧室（栈、程序计数器）。

## 重点来了：线程在 JVM 里独享了什么？

这个问题要从 JVM 运行时数据区说起。JVM 把内存划分为几个区域，有的是所有线程共享的，有的是每个线程独享的。

```
JVM 运行时数据区

  线程私有：
    ① 程序计数器（PC Register）
    ② 虚拟机栈（JVM Stack）
    ③ 本地方法栈（Native Method Stack）
    （每个线程一份，互不干扰）

  线程共享：
    ④ 堆（Heap）
    ⑤ 方法区（Method Area / Metaspace）
    （所有线程都能访问）
```

下面一个一个说线程私有的三块。

### ① 程序计数器（PC Register）

JVM 规范里的原话：

> "Each Java Virtual Machine thread has its own pc (program counter) register."

程序计数器就是一个很小的内存空间，记录**当前线程正在执行的字节码指令的地址**。

为什么要线程私有？因为 CPU 在多线程之间来回切换，线程被切走的时候需要记住"我执行到哪了"，等回来的时候从断点继续。如果大家共享一个计数器，那切换回来就不知道该从哪继续了。

```java
// 想象一下两个线程执行不同方法
// 线程 A 执行到了第 5 条字节码指令
// 线程 B 执行到了第 12 条字节码指令
// 如果共享同一个 PC，CPU 切回线程 A 时还以为要执行第 12 条...那就乱了
```

有个细节：如果线程执行的是 native 方法，PC 的值是 **undefined**（未定义）。因为 native 方法不是字节码，JVM 管不着。

> 另外之前那篇 OOM 的笔记也提过，程序计数器是 JVM 里**唯一一个不会 OOM 的区域**——因为它就存一个地址值，空间固定且极小。

### ② 虚拟机栈（JVM Stack）

JVM 规范：

> "Each Java Virtual Machine thread has a private Java Virtual Machine stack, created at the same time as the thread."

虚拟机栈跟线程**同生共死**——线程创建时栈就建好了，线程结束栈就销毁。

**栈里面装的是什么？** 每调用一个方法，就会创建一个**栈帧（Stack Frame）** 压入栈中；方法执行完毕，栈帧弹出。

一个栈帧里面包含：

```
栈帧（Frame）
  局部变量表 (Local Variables)       ← 方法的参数和局部变量
  操作数栈 (Operand Stack)           ← 方法执行过程中的临时数据
  动态链接 (Dynamic Linking)         ← 指向运行时常量池中方法的引用
  方法返回地址 (Return Address)       ← 方法执行完该回到哪
```

拿一段代码感受一下：

```java
public int add(int a, int b) {
    int result = a + b;
    return result;
}
```

调用 `add(3, 5)` 时，JVM 创建一个栈帧：

- **局部变量表**：slot 0 存 `this`（实例方法的话），slot 1 存 `a = 3`，slot 2 存 `b = 5`，slot 3 存 `result`
- **操作数栈**：先把 `a` 和 `b` 压栈，执行 `iadd` 指令弹出两个做加法，结果压回栈里
- **方法返回地址**：记录调用方的下一条指令位置

> 这也是为什么局部变量是线程安全的——每个线程有自己的栈，栈帧里的局部变量自然是隔离的。但如果局部变量是一个引用类型指向堆上的对象，那对象本身还是共享的，这点不能搞混。

**虚拟机栈的两种异常：**
- `StackOverflowError`：栈深度超过限制（比如无限递归）
- `OutOfMemoryError`：创建太多线程，每个线程分配栈空间，总内存不够

可以通过 `-Xss` 参数调整每个线程的栈大小，默认一般是 512k 或 1m（取决于平台）。

### ③ 本地方法栈（Native Method Stack）

跟虚拟机栈的作用差不多，只不过它服务的是 **native 方法**（用 C/C++ 等写的方法，通过 JNI 调用）。

JVM 规范说了：

> "If supplied, native method stacks are typically allocated per thread when each thread is created."

也是线程私有的，也可能抛 StackOverflowError 和 OutOfMemoryError。

在 HotSpot 虚拟机里，本地方法栈和虚拟机栈是合二为一的，不做区分。所以实际开发中一般不需要单独关注它。

## 再看看线程共享的区域

虽然题目问的是线程独享的，但对比着说一下共享区域会更清楚。

### 堆（Heap）

JVM 规范原话：

> "The Java Virtual Machine has a heap that is shared among all Java Virtual Machine threads."

所有 `new` 出来的对象实例和数组都在堆上分配。这也是 GC 的主战场。

正因为堆是共享的，所以**多线程操作同一个对象才会有并发安全问题**。

### 方法区（Method Area / Metaspace）

> "The Java Virtual Machine has a method area that is shared among all Java Virtual Machine threads."

存的是类的元数据——类信息、常量池、静态变量、JIT 编译后的代码等。JDK 8 之前叫永久代（PermGen），之后改成了元空间（Metaspace），用的是本地内存。

## 为什么这么设计？

这个设计背后的逻辑其实很清晰：

1. **程序计数器必须私有**：线程切换后要能恢复执行位置
2. **栈必须私有**：方法调用的局部状态不能被其他线程干扰，否则方法执行就乱了
3. **堆必须共享**：对象要在线程间传递和共享，不可能每个线程都复制一份
4. **方法区必须共享**：类只需要加载一次，所有线程用同一份类定义就行

> 换个角度想——线程私有的都是"执行状态"相关的（执行到哪了、调用了什么方法、局部变量是多少），线程共享的都是"数据"相关的（对象在哪、类定义是什么）。**执行状态天然需要隔离，数据天然需要共享。**

## 容易混淆的点

**ThreadLocal 是线程私有的吗？**

严格来说不是 JVM 层面的"线程私有区域"。ThreadLocal 的数据实际上存在堆上（`Thread` 对象里有个 `ThreadLocalMap` 字段），只是通过 API 设计让每个线程访问自己的副本。它是 Java 语言层面的线程隔离，不是 JVM 内存区域层面的。

**局部变量一定线程安全吗？**

基本类型的局部变量是安全的，因为在栈帧里，完全隔离。但如果局部变量是个引用类型：

```java
public void doSomething() {
    // list 引用在栈上（私有），但 ArrayList 对象在堆上（共享）
    List<String> list = sharedList; // 如果 sharedList 是共享的
    list.add("data"); // 这行就不是线程安全的
}
```

引用本身在栈上是安全的，但它指向的对象在堆上，可能被多个线程同时操作。

## 小结

进程和线程的区别，核心就是资源隔离程度的不同。映射到 JVM 里面，线程独享的三块——程序计数器、虚拟机栈、本地方法栈——都是为了保证线程能独立执行不互相干扰。搞清楚哪些私有哪些共享，对理解并发编程中的线程安全问题帮助挺大的。
